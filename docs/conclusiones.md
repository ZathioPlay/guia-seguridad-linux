

\# Conclusiones y Buenas Prácticas



El dominio de Git elimina el riesgo de pérdida de información y sustituye prácticas ineficientes (como guardar copias llamadas `proyecto\_final\_v2.zip`) por un historial trazable, limpio y reversible.



\## Ventajas principales comprobadas



\* \*\*Trazabilidad total:\*\* Cada línea modificada queda asociada a un autor, una fecha y un mensaje descriptivo.

\* \*\*Colaboración asíncrona:\*\* Varios integrantes pueden avanzar en paralelo sobre el mismo proyecto desde distintos equipos.

\* \*\*Despliegue continuo:\*\* Integración directa con plataformas como \*\*GitHub Pages\*\* para publicar documentación web en segundos.



\## Buenas prácticas recomendadas



\* \*\*Commits atómicos:\*\* Realizar confirmaciones pequeñas y frecuentes que agrupen cambios relacionados entre sí.

\* \*\*Mensajes descriptivos:\*\* Utilizar prefijos claros (`feat:`, `docs:`, `fix:`) en lugar de mensajes genéricos como \*"cambios"\*.

\* \*\*Uso de `.gitignore`:\*\* Excluir siempre carpetas temporales, entornos virtuales (`venv/`) o credenciales privadas antes de subir código.



??? question "Glosario rápido de comandos esenciales"

&#x20;   \* \*\*`git clone`:\*\* Descarga una copia completa de un repositorio remoto en tu equipo.

&#x20;   \* \*\*`git diff`:\*\* Muestra línea por línea las diferencias exactas antes de confirmar un cambio.

&#x20;   \* \*\*`git log --oneline`:\*\* Resume el historial de confirmaciones de forma compacta.
